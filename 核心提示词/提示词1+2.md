# 十一、Workspace

Workspace 是整个 Runtime 的核心。

但是必须明确：

**Workspace ≠ LLM Context**

Workspace 是某次 Pipeline 执行产生的数据环境。

例如：

```text
Workspace

├── inputs
├── node_results
├── datasets
├── features
├── models
├── predictions
├── metrics
├── visualizations
├── artifacts
├── execution
├── metadata
└── history
```

例如：

```text
node_003.output.features
```

真实数据可以存：

```python
workspace.node_results["node_003"]["features"]
```

可能是：

```text
100000 × 128 DataFrame
```

Graph/XML 中只保存：

```text
node_003
output port = features
```

而不会保存实际矩阵。

# 十三、Runtime State

不要使用原来简单的：

```text
DATA_READY
FEATURE_READY
PREDICTED
```

来限制整个系统，因为现在方案是任意 Graph。

应该维护两个级别状态。

## Pipeline Status

```text
CREATED
VALIDATING
READY
RUNNING
SUCCESS
FAILED
CANCELLED
```

## Node Status

```text
PENDING
READY
RUNNING
SUCCESS
FAILED
SKIPPED
```

每个 Node 独立维护执行状态。

这样可以支持任意 DAG。

# 十四、Execution Engine

建立：

```text
ExecutionEngine
```

它不依赖 LLM。

执行流程：

```text
ComponentGraph
      ↓
Graph Validation
      ↓
Port Type Validation
      ↓
Parameter Validation
      ↓
Cycle Detection
      ↓
Topological Sort
      ↓
Ready Node Detection
      ↓
Execute Component
      ↓
Save Output to Workspace
      ↓
Propagate OutputPort
      ↓
Downstream Component
      ↓
Final Result
```

每个 Component：

```python
result = component.execute(inputs, parameters, context)
```

Runtime 将：

```text
result.outputs
```

写入 Workspace。

# 十五、中间数据传递原则

组件连接只描述逻辑关系。

例如：

```text
node_A.features
      ↓
node_B.features
```

ExecutionEngine 真正执行时：

```python
value = workspace.get_output(
    node_id="node_A",
    port="features"
)
```

然后注入：

```python
node_B.execute(
    features=value
)
```

组件之间不要直接持有彼此引用。

# 五十二、核心设计原则

必须严格遵守：

1. Component 是整个系统最核心的抽象。

2. 一个 Component 应尽量对应一种原子能力。

3. Python 底层函数不等于 Component。

4. Component 不等于 MCP Tool。

5. Component 之间通过 Port 交换数据。

6. Port 必须具有 DataType。

7. Parameter 必须 Schema 化。

8. ComponentRegistry 是组件定义统一入口。

9. ComponentGraph 表示方案结构。

10. XML 是 Graph 的持久化格式。

11. XML 不保存大型运行数据。

12. Workspace 保存运行时数据。

13. ExecutionEngine 负责 Graph 执行。

14. LLM 不参与底层正确性判断。

15. MCP 负责 Agent 操作 ComponentGraph。

16. Skill 负责教 Agent 如何构建专业 Pipeline。

17. Visual Designer 和 MCP 必须操作同一个 Graph Model。

18. 人工和 Agent 创建的 Pipeline 完全兼容。

19. 新增 Component 不要求修改 Runtime 核心。

20. UI 参数面板自动根据 Parameter Schema 生成。

21. UI 组件库自动根据 ComponentRegistry 生成。

22. Graph 必须支持类型校验。

23. Graph 必须进行循环依赖检查。

24. Pipeline 必须可以完整 XML 序列化和反序列化。

25. Workspace 支持 Checkpoint。

26. Node 必须保存执行 History。

27. 大型数据不进入 LLM Context。

28. Agent 只接收 Summary / Metadata / Result Preview。

29. Runtime 必须能够独立于 Agent 使用。

30. 整个平台即使没有任何 LLM，也应该能够由人工正常使用。

最终请始终围绕一个原则：
